# 画面ユースケースとRaycastの検証

build 15で追加、build 16でRaycast受信とルート検索、build 17で呼び出し時の前面化を修正、build 18で音声受付への割り込みと途中の指示の保持に対応。`scripts/test.sh` はSwift 150件、worker 53件、報告スクリプト3件が通過。RaycastはTypeScript型検査、Nodeの4件のテストが通過。公式CLIのビルドはbuild 16時に確認。`scripts/audit-public.py` と `git diff --check` も通過。

- 初期2件、旧設定からの移行、削除後の空配列維持、独自設定・表示言語変更時の保持を検証。
- 2,400件のユースケースを設定して検証・JSON復元。旧1MB制限を超えた設定も読み込み、他用途の明示的な読み込みサイズ制限は維持。
- テンプレート風の文字列を含むプロンプト/OCRをそのまま保持し、空のOCR・長すぎる本文を検証。
- 保存済みの宛先・プロンプト・読み上げ・確認設定を使う送信を、PNG付きのモックHTTPで検証。マイクを起動しないこと、読み上げOFFで監視しないこと、連打・停止・画面取得失敗時に送信しないことを確認。
- Carbonの登録とイベント配送を使い、ユースケース別の識別、キーを押し続けた場合の重複抑制、キー解放後の再実行、登録差し替えを検証。
- Raycast一覧に有効項目・ホットキーなし項目を含め、プロンプト・宛先を含めないことを確認。要求ファイルの権限、URL解析、期限、再実行拒否、対象アプリの制約、削除/無効化済み項目・受付拒否時の動作を検証。
- 日本語の標準サイズ・最小サイズ、および展開した編集画面をサンプルデータで描画して確認。
- build 15で実URLを使う無効IDの要求が未消費のままタイムアウトすることを再現。初期化時のApple Event登録をSwiftUIのアプリデリゲートへ移し、build 16では同じ要求に受付拒否の応答が返ることを実機確認。画面取得・送信は発生しない。
- コマンドライン実行とデリゲート間の要求・受付応答、受付拒否、削除済み項目、要求ファイルの削除をテスト。
- 有効なユースケースごとのScript Command生成、名前変更、無効化・削除時の同期、無関係なファイルの保持、改行入り名称とシェル特殊文字を含むパスをテスト。
- 署名付きbuild 16を起動し、生成先フォルダをRaycastに登録。`talk` の入力だけで2件が直接表示されることを実機確認。旧一覧コマンドはRaycast設定で無効化。
- 要約だけ一時的に送信前確認をONにし、Raycastの要約候補を実行。前面ウィンドウの画像・OCR・保存済みプロンプトを含む確認画面に到達。取り消して送信せず終了し、送信前確認はOFFへ復元。検証中の画像・OCRはリポジトリに保存していない。
- build 17は実行要求を起動URLからプロセス間通知へ変更。通知の宛先分離、受付応答、同じIDの重複通知を無視して応答を保持することをテスト。通常のモック送信でウィンドウを表示しないことも確認。
- 署名付きbuild 17およびbuild 18へ、未登録IDの要求を実際のコマンドライン経路で送って検証。build 17では停止中からの非表示起動と起動済みの両方、build 18では停止中からの非表示起動で `requestRejected=true, foregroundPreserved=true, appActivations=0, exit=0`。要求の処理後1秒まで監視し、画像取得もWebex送信も行っていない。検証手順は `scripts/check-raycast-background.swift` に保存。

- build 18は待受・録音・認識・送信準備・追加発話受付中に実行可能。途中の音声、認識済みの指示、元の設定・スレッド宛先を保持し、完了・取り消し・画面取得失敗後に続きを追加できることをモックで検証。長い一時停止が発話待ちの期限や録音区間に加算されないことも検証。
- 認識途中の古い結果を無視し、未処理の音声だけを再認識。録音途中のサンプル保持、25秒上限や待ち行列制限の維持、マイク再開失敗時に再試行が循環しないことを検証。
- 音声POSTの送信中はマイクと入力期限を止め、対象画面を先に取得して送信完了を待つ。成功した音声POSTは再送せず、画面操作後に追加発話へ戻る。成否不明・明示的な拒否・手動停止では画面POSTを行わないことを検証。
- 画面操作を挟んだ音声の返信監視で、画面の要求により監視を誤終了せず、紐づかない返信や画面側の返信を候補から除くことをモックで検証。

実画面を使うホットキー/RaycastからWebex送信・最終返信の読み上げまでの通し確認は未実施。今回のRaycast実機確認は送信前確認画面までとし、送信・読み上げ経路はモックで検証した。UI操作ツールの前面切り替えにより想定したサンプル文書ではなく、その時点の前面ウィンドウが取得された。物理ホットキーの通し確認と、通常操作時に狙ったアプリへ戻る確認は別途必要。

build 18は署名付きアプリへ反映済み。実マイクで待受を開始してRaycastから割り込む追加確認は、再起動後の保存済みトークンの読み込み許可待ちで未実施。音声保持・再開の検証は上記の自動テストによる。

macOSのVision・音声フレームワークを使う既存テストは、制限環境内ではOCR失敗と音声エンジンの異常終了が発生するため、通常の実行環境で検証した。ソースにテスト回避は加えていない。
