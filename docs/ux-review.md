# UI/UXレビュー

2026-09-09、ビルド8の実装を対象に、初回設定・日常の音声操作・失敗からの復帰をレビューしました。ソースと状態遷移の点検、一般的なサンプルによる画面描画、自動テストを組み合わせた評価です。利用者を集めたユーザビリティ調査ではありません。

## 評価基準

Macで慣れた設定の配置、必要な選択肢への到達しやすさ、適切な初期値を基準にします。設定の検索、標準フォーム、⌘,による設定への移動を採用しています。[Apple HIG: Settings](https://developer.apple.com/design/human-interface-guidelines/settings)

現在の状態、操作結果、次にできることを同じ場所で示し、通常の状態変化を不要なダイアログにしないことを基準にします。対処が必要な認証更新と、任意の送信前確認には専用の画面を使います。[Apple HIG: Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback)

5秒の録音は実際の経過に対応した進捗、API応答待ちはスピナーとして表示します。未確定の処理に完了率を作らず、停止操作を残します。[Apple HIG: Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)

## 問題と修正

以下の問題の評価と具体的な修正方法は、このアプリの操作フローに基づく判断です。

| 優先度 | 操作上の問題 | 修正後の動作 |
| --- | --- | --- |
| 高 | 待受を始めても、準備不足の解決先が分からない | ホームに権限・認証・宛先・音声環境のうち次に必要な準備と移動ボタンを表示。開始できない理由を近くに出す。 |
| 高 | キーチェーンの許可とWebex APIの確認が混同される | アクセス不足時の読み込みボタンを折り畳みの外へ表示。自動読み出し失敗と手動で拒否された場合を別の文面で案内。認証確認中を表示して多重実行を抑止。 |
| 高 | DM選択や参照録音の登録で、別の未保存設定まで保存される | 通常設定は保存・取り消しに統一。開始時に保存する場合はボタン名にも表示。API Keyと録音はその項目だけを保存する。 |
| 高 | 25秒の背景音で常時待受が停止する | 長い区間と古い認識結果を破棄して待受を続ける。指示受付と返信監視の期限は待受全体の終了と分ける。復旧不能な入力・認証エラーには対処を案内する。 |
| 高 | 任意のスクショが取得できないと音声の指示も送れない | 対象不在、前面変更、ロック、取得失敗では画像・OCRをまとめて省略。確認画面とログに省略を表示する。権限不足は事前に解決する。 |
| 高 | 長い音声生成の上限で返信の後半が読めない | 句読点・記号・改行を使って最大32文字に事前分割。上限に達した未再生区間はさらに分割して生成し直し、順番に再生する。 |
| 中 | 返信先の引用と、実際に送る本文の区別が曖昧 | 確認画面の引用を「返信先の確認用」と表示。送信文は新しい発話と文脈継続の指示だけにする。 |
| 中 | 短い認識処理のたびに大きな状態名が変わり落ち着かない | 常時待受の見出しを「合言葉を待っています」「指示を受け付けています」に整理。内部の計測結果はログへ分離する。 |
| 中 | 5秒テストの終了時刻が分からず、診断を開くと履歴の領域が狭くなる | 実経過の録音進捗を表示。診断パネルに高さの上限とスクロールを設け、履歴を残す。狭い幅ではログ操作と検索の配置を切り替える。 |
| 中 | 設定値のエラーで、直すべき項目が分からない | 項目名と許容範囲を個別に案内。ms表記と更新停止待ちの秒数を分けて表示する。 |
| 中 | 参照音声の録音中に別の設定も編集できる | 録音終了の操作は使えるまま、合言葉・音声方式・待ち時間などの変更を無効にする。 |
| 中 | 設定名を知らないと必要な項目が見つからない | 「キーチェーン」「ポーリング」「ロック」など関連語を項目検索で受け付ける。ホームの機能表示から該当設定へ移動できる。 |

## 採用した判断

保存操作は送信先やテンプレートの一貫性に関わるため、通常設定では明示保存を維持しました。ユーザが操作するたびに確認ダイアログを増やさず、未保存表示・取り消し・保存を同じ場所に置きます。

マイクと画面収録の権限は、音声で操作を始める前に確認します。音声操作中に権限画面へ誘導しないというこのアプリの要件を優先しています。API Key失効時のブラウザ起動は一度に限り、後からアプリ内で更新を再開できます。

画面ロック中も使うため、開始した待受中だけアイドルによるシステムスリープを抑止します。画面ロックを解除したりディスプレイを点灯し続けたりする機能ではありません。送信前確認がONなら、ロック解除後の確認を待ちます。

## 検証と残る確認

- 880×650と1080×780のソース画面、明暗のホーム、設定、ログと診断、画像省略とスレッド返信の確認画面を描画して確認。個人データは使っていません。
- 主要な状態遷移・本文生成・移行・権限・録音形式は自動テストで確認。音声の分割と上限後の再生成はネットワーク禁止下で実モデルも使用。
- オフスクリーン描画ではmacOSのサイドバーが合成画像に入らないため、サイドバー単独も描画。実アプリの合成表示、項目選択、VoiceOver、キーボードだけの完走は未確認です。
- 本人参照音声を使った新しい分割方式の長文試聴では、途中停止・繰り返しなく末尾まで読めたことをユーザが確認しました。ロック中の実マイク入力、会議アプリとの同時使用、数時間の常駐、実返信全般の聴感は未確認です。
- ロック除外では公開のCGSession APIの辞書を使いますが、ロック状態のキーは公開契約として文書化されていません。前面アプリ・オンコンソール状態も検査し、OS更新時を含めてロック中の取得省略をE2Eで確認します。

実行結果は[検証記録](validation.md)、実機での確認順は[E2E手順](e2e.md)に記載します。実測前に使いやすさや音声精度を改善率として数値化しません。

## ビルド10の読み上げ

試聴欄の説明を、改行ごとの生成・最初の2行の準備・再生中の先行生成に合わせた。行ごとの生成時間と先行音声不足は診断ログにまとめ、通常の読み上げ中に追加の確認や設定操作は要求しない。画面の操作・配置は継続する。実際の聞こえ方と行間の連続性は本人の試聴で確認する。

## ビルド11の読み上げ開始

試聴欄を「冒頭の音声ができ次第読み始め、その後は改行に沿って先行生成する」という説明に更新した。追加の操作や速度設定を要求せず、開始待ちの短縮を既定の動作にした。行間の待ちと本人の聴感は実際の試聴で確認する。

## ビルド12の参照音声ノイズ軽減

Qwenの参照録音の下に「参照音声の背景ノイズを軽減」を追加し、初期ONにした。声の響きが変わる場合にOFFの音声と比較できる説明を付けた。既存の試聴ボタンと保存・取り消しを使用し、ノイズ低減の細かな数値設定は要求しない。元録音への変更は行わない。

## ビルド13の報告・プライバシー操作

生成アイコンをDock・Finder・サイドバーに統一した。停止中はサイドバー、ログ、ヘルプから不具合報告の下書きを開ける。症状と再現手順は利用者が追記し、環境情報と既知の診断イベントだけを自動挿入する。コピーと報告フォームを開く操作を用意し、アプリからは自動投稿しない。

ホームの「表示を消去」で画面内の会話とスレッド返信先を消せる。処理中の消去は無効にし、Webex上のメッセージを削除する操作とは区別した。診断ログの消去には確認を追加した。

報告シート、サイドバーのアイコン、880×650のログ画面をサンプルデータで描画し、操作ボタンと説明の収まりを確認した。全設定と明暗ホームも再描画した。VoiceOverによる全操作と、GitHubへの実投稿は今回の検証に含めない。
