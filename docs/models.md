# ローカルモデルの選定

調査・検証日: 2026-09-09。数値は条件によって変わります。モデルそのものはリポジトリへ同梱せず、ユーザの明示操作で取得します。

## 文字起こし

**MLX Whisper large-v3-turboを既定に採用します。** Apple Siliconでの推論、日英混在を含む多言語モデル、日本語固定の復号、認識信頼度の取得が既存構成と合います。large-v3は精度比較の選択肢として残します。[MLX公式実装](https://github.com/ml-explore/mlx-examples/tree/main/whisper)、[採用モデル](https://huggingface.co/mlx-community/whisper-large-v3-turbo)

| 候補 | 利点 | この用途での扱い |
|---|---|---|
| Whisper small / medium | モデルを小さくできる | 日本語の実録音比較なしに精度十分とは扱わない。今回は未測定 |
| Whisper large-v3 | 多言語の認識品質を比較する基準 | オプション。今回の合成音声では同等の意味を認識したが、表記差があり、待機後の推論はturboより遅かった |
| Whisper large-v3-turbo | large-v3のデコーダを縮小した高速モデル | 短い対話の応答速度を優先して既定に採用 |
| Distil-Whisperの英語中心モデル | 英語の高速処理 | 日本語中心の本用途では採用しない |

Whisper公式のパラメータ数はlargeが約1.55B、turboが約809Mです。公式のVRAM・相対速度表は英語・A100での参考値で、MacのMLX実測とは異なります。日本語の精度は話者、雑音、専門語で変わります。[Whisper公式比較](https://github.com/openai/whisper#available-models-and-languages)

### Macでの実測

M4 Pro、24GB、macOS 26.6.2。Mac標準の日本語音声から作った4.7〜6.1秒の3文を使用。ネットワーク禁止sandbox、`mlx-whisper 0.4.3`、固定したモデルで、VAD・ノイズ処理を含むworkerの処理時間を測定しました。

| 指標 | turbo | large-v3 |
|---|---:|---:|
| 最初の1文（モデル初回読込含む） | 5.029秒 | 3.947秒 |
| 2文目（読込済み） | 0.554秒 | 0.955秒 |
| 3文目（読込済み） | 0.526秒 | 0.824秒 |
| プロセス最大RSS | 1.155 GiB | 3.540 GiB |
| MLXが報告したピークMetalメモリ | 2.298 GiB | 3.678 GiB |

RSSとMetal値は異なる測定指標で、単純に足して総消費量とはしません。初回時間はOSキャッシュや他処理にも影響され、ここではturboの初回が速いとはいえません。短い3文での比較に限り、継続推論速度とMetalメモリを理由にturboを選んでいます。

両者とも3文の指示の意味を認識しました。数字が「三」から「3」に変わり、large-v3では「オッケー」が「OK」になりました。評価スクリプトのCERは句読点・空白を除きますが数字・読みの同値変換をしないため、この表記差も誤りとして数えます。実録音の一般的な日本語精度を示すベンチマークではありません。合言葉の別表記はアプリに追加できます。

```bash
scripts/download-models.sh asr-large
scripts/smoke-local.sh --model whisper-large
```

比較用モデルはアプリのASRパスをアプリ用データフォルダ内の `models/whisper-large` に変更して試せます。実録音を比較する際は音声をGitへ入れず、個人名・専門語を含む結果も公開しないでください。

## 読み上げ

### Mac標準音声

取得済みの日本語音声を使います。モデル追加や参照音声なしで起動・読み上げを確認する既定方式です。本人の声にはなりません。アプリは声を自動取得せず、`say` をネットワーク禁止下で呼び出します。実機では標準音声からWAVを生成する経路に加え、ユーザ操作によるWebexの最終返信の読み上げを確認しました。

### Sarashina2.2-TTS

日本語中心、短い参照音声による声の再現を目的とした候補です。ただしモデルは **Sarashina Model NonCommercial License Agreement** で配布され、商用目的は提供者への問い合わせが案内されています。モデル紹介ページのサンプル音声にも再配布・商用利用の制限があります。[公式モデルカード・配布条件](https://huggingface.co/sbintuitions/sarashina2.2-tts)

公式の導入例はGPU利用のDocker、Transformers、任意のvLLMを中心とし、この調査ではApple Silicon / Metalでサポートされた動作手順を確認できませんでした。Macで不可能と断定するものではありませんが、本アプリでのMac動作を確認したとは扱えません。公式生成経路には音声の電子透かしも含まれます。[公式実装](https://github.com/sbintuitions/sarashina2.2-tts)

用途が業務を含むか未確定でも使いやすく、Mac上で検証できる構成を優先し、現時点ではSarashinaを組み込みません。

### Qwen3-TTS 0.6B Base（MLX 4bit）

日本語対応、参照音声による声の再現ができるBaseモデル、Apache 2.0の配布条件を理由に採用します。公式は3秒の参照による音声再現を説明していますが、本アプリでは録音品質の安定のため10〜20秒と正確な書き起こしを推奨します。公式PyTorchのCUDA例をMacで動作確認済みとはみなさず、MLX Audioの実装と変換済み重みを使用します。[Qwen公式](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base)、[MLX重み](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-0.6B-Base-4bit)、[MLX Audio実装](https://github.com/Blaizzy/mlx-audio)

`mlx-audio 0.4.8` の実APIを確認し、`lang_code="Japanese"`、ローカル参照音声・参照本文、同梱speech tokenizerを使う経路を実行しました。通常実行で追加モデルを取りに行く必要はありません。

合成日本語音声を参照に、約5.551秒の新しい音声を16.810秒で生成しました。再度Whisperで認識した結果は生成指定文と同じ意味でした。ASRとTTSを同じプロセスで使ったときのMLXピークメモリは6.703 GiBでした。再実行では約5.47秒の音声を9.79秒で生成し、ピークMetalメモリは7.201 GiBでした。OSキャッシュ、同時処理、生成結果により時間とメモリが変動します。これらは合成音声での性能測定です。音声生成は標準音声より待つ可能性があり、長文はさらに時間がかかります。

その後、ユーザがアプリ内で本人の参照音声と正確な本文を登録し、短い試聴文を生成しました。本人から「自分の声に似ている」と確認を得ています。これはその参照録音・試聴文での本人評価であり、長文や異なる感情表現の品質まで確認したものではありません。モデルの追加学習は行っていません。

読み始めの待ち時間を抑えるため、冒頭だけは短い文または自然な区切りで32文字以内に分割します。その後は空行を除いた1行ごとに独立して生成し、160文字以内の行は句読点を含めてそのまま渡します。160文字を超える行はまず文末で区切り、長すぎる文だけ句読点・記号・macOS内蔵の単語境界で事前分割します。ひらがなの語尾やカタカナ語の途中を避け、短い文末だけが残らない位置を優先します。追加モデルや通信は不要です。20,000文字を超える本文は明示エラーとし、黙って先頭だけを読みません。各生成には長さに応じて5〜24秒相当のトークン上限を設けます。上限に達した未再生区間は同じ境界判定で最大3段階まで分割して生成し直し、断片を結合してから再生へ渡します。短い区間でも生成できない場合、非有限音声、サンプルレート不整合はエラーにします。

最初の音声ができた時点で再生を開始し、2区間目の生成を待ちません。再生中も次の行を生成します。推論は1つのモデルで直列に実行し、音声エンジンの再生と並行させます。再生待ちが2区間以下かつ30秒以下になったところで次の生成を始めるため、保持するPCMは原則として最大3区間です。長さ上限後の断片を結合した区間は24秒を超える場合があります。停止・失敗では先行音声を破棄します。生成速度が再生に追いつかない場合の行間の待ちや、上限未満の誤発音・反復をすべて防げるわけではありません。

参照録音の背景ノイズが音声の「間」に再現されることへの対策として、読み上げ用の参照音声をメモリ上で軽くノイズ低減します。20msのフレームの静かな15%をノイズ推定に使い、発話との差が十分ない録音や、もともと極めて静かな録音は処理を省きます。録音のタイミングと全文を保ち、元ファイルには書き込みません。準備した参照音声は録音の更新・サンプルレート・ON/OFFでキャッシュを切り替えます。声の響きが変わる場合は「参照音声の背景ノイズを軽減」をOFFにできます。[ノイズ調査とモデル比較](speech-quality.md)も参照してください。

## VAD・ノイズ抑制・話者照合

Silero VADはwheelに含まれる重みを使います。任意で有効にできるAVAudioEngineの追加音声処理、80〜7600Hzの帯域フィルタ、弱いスペクトルノイズ抑制を併用します。Whisperのno-speech、平均log probability、compression ratioを確認し、一部の区間が不確かな場合は発話全体を拒否します。

Resemblyzerは声の比較用のローカル埋め込みを作ります。初期値の「登録した声を優先」は利便性を優先し、短い発話や単独発話を類似度だけでは拒否しません。同じ録音内の間を置いた発話どうしを比較し、参照に十分近い声があり、他の声との相違も大きい場合だけ優先する発話を選びます。同時発話の音源分離は行いません。以下は、任意の「厳格に本人照合」に適用する条件です。

短いVAD区間を個別に比べると、モデル内部で1.6秒へゼロ埋めされ、本人の発話でも誤拒否する事象を実機で確認しました。このため音声区間を連結し、全体と1.6〜3秒の重なる窓の類似度を比較する方式へ修正しました。末尾だけの短い窓は作らず、全体またはいずれかの窓がしきい値未満なら拒否します。

短い合言葉は先に検出し、指示の音声がそろった段階で照合します。照合対象に1.6秒以上の音声区間がなければ、長く話すよう案内します。本人の別録音では、しきい値を維持したまま誤拒否が解消することをオフラインで確認しました。

同一合成音声での初期比較では約0.947でした。この値は本人と他人の識別性能を証明しません。別話者、短い相づち、再生音声、重なった話者への耐性は実録音で評価する必要があります。ライブラリの互換性のためsetuptoolsを81未満に固定しています。

## ホットスタンバイと逐次生成

返信監視と並行してモデルを読み込み、短い準備推論で参照音声コードをキャッシュします。準備音声は再生・保存しません。各区間の生成完了後に長さの上限を確認してから、AVAudioPlayerNodeへ渡します。再生用PCMは0.5秒以下に分けて進行を計測し、上記の先行上限まで次の行を準備するため、生成と再生が重なります。停止時にworkerと再生を終了します。

文ごとの生成方式で、一般的な合成参照音声を使い、8文の日本語・カタカナの読みを2回生成しました。先行準備は3.486秒、最初の1文は0.673秒と0.702秒、21.84秒と23.20秒の音声全体は5.423秒と5.465秒で生成しました。ピークMetalメモリは4.004 GiBでした。Whisperの再認識では2回とも全8文の内容を確認しました。音声を実再生して評価した結果ではなく、実際の本人参照音声・長い実返信の発音や声質は別途確認が必要です。

## Macのスピーカー音と同時発話

現在の話者優先は、間を置いた発話の選択です。二人が同時に話す音声から本人だけを取り出す処理は実装していません。登録音声の主な周波数帯だけを残しても、他の人の声の成分が同じ帯域に重なり、本人の子音なども落とす可能性があります。帯域フィルタを本人専用の音声分離として扱いません。

相手の声がMacのスピーカーから再生されている場合は、再生音のマイクへの回り込みを抑えるエコーキャンセルが候補です。AVAudioEngineの音声処理にはエコーキャンセルなどが含まれます。これは本人の参照録音による照合とは別です。[Appleの音声処理解説](https://developer.apple.com/videos/play/wwdc2019/510/)

アプリでは「音声入力」→「マイクの詳細」→「Macの追加音声処理」で切り替えます。過去の無入力事象を受けて初期OFFにしています。ビルド8の実機で、ONにすると待受開始時に会議のスピーカー音量が下がると報告され、OFFへ戻しました。会議音量を維持する用途ではこの設定を有効にしません。機器・音声経路による認識への効果も未確認です。音声処理には他アプリの再生音量を下げるダッキングが伴います。[Appleの他音声ダッキング解説](https://developer.apple.com/videos/play/wwdc2023/10235/)

同じ部屋の生の声など、再生元の信号を利用できない重なりには、登録した声を手掛かりに混合音声から取り出す対象話者抽出が候補になります。SpeakerBeamはそのための研究実装です。現行アプリへの組み込みやMacでの性能評価を済ませたものではありません。[SpeakerBeam公式実装](https://github.com/BUTSpeechFIT/speakerbeam)
