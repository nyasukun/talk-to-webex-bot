# 読み上げの「間」のノイズ調査

2026-09-09、Apple M4 Pro・24 GBのMacで、登録済みの参照録音と指定された10行の文章を使って検証した。文章・録音・個別の認識結果は公開コードに含めない。推論中はネットワークを禁止し、テスト音声はスピーカーで自動再生していない。

## 確認したこと

6条件で各2回、合計12回の全文生成を行った。乱数種を各条件でそろえ、行の音声長、生成時間、静かな区間の音量、Whisperの再認識を比較した。疑わしい箇所の一部はWhisper large-v3でも再確認した。これは波形解析と自動音声認識による評価で、人間による聴感評価ではない。

- 行と行の接合点に、通常の音声波形を大きく上回る瞬間的な跳躍は見つからなかった。既存のAVAudioEngineオフラインテストでもPCMの欠落・重複は検出していない。
- 生成音声の文章内の間にも低い音が残っていた。参照録音の静かな区間と生成音声の低音量部分には、いずれも約−54 dBFS程度の背景成分があった。
- 参照録音だけを軽くノイズ低減してから生成すると、出力の静かな部分と文中の間の音量が下がった。参照録音の背景音が再現されることが有力な原因。ただし、ユーザが聞いた特定の異音と一致するかは聴感確認が残る。
- 読みの揺れは別の問題として残った。人名の読み違いは2種類の認識モデルで共通だった。一方、ある文末の崩れは認識モデルによって結果が異なり、不具合と断定していない。

## 比較結果

| 条件 | 最初の音声生成（2回） | 静かな部分の中央値 | 文中の間の中央値 |
| --- | --- | --- | --- |
| ビルド11相当 | 0.67 / 0.61秒 | −52.9 dBFS | −51.7 dBFS |
| 行全体をまとめて復号 | 2.66 / 1.56秒 | −53.2 dBFS | −51.9 dBFS |
| 生成温度0.6 | 0.63 / 0.71秒 | −53.6 dBFS | −52.4 dBFS |
| 参照ノイズ低減0.85（一時ファイル） | 0.44 / 0.60秒 | −68.0 dBFS | −60.1 dBFS |
| 参照ノイズ低減0.65（一時ファイル） | 0.81 / 0.62秒 | −61.4 dBFS | −57.2 dBFS |
| ビルド12実装：参照ノイズ低減0.65（メモリ上） | 0.85 / 0.56秒 | −62.8 dBFS | −59.8 dBFS |

静かな部分は各生成音声の20msフレームRMSの10パーセンタイルを求め、20音声で中央値を取った値。文中の間はASRの単語時刻で0.3秒以上ある間から両端60msを除いてRMSを計算した値。生成ごとに発話や間の位置が変わるため、同一の音声を加工した前後比較ではない。ASR時刻は完全ではなく、息や弱い発音を含む可能性もある。

最初の音声生成は準備済みモデルからの測定で、モデル読み込み、返信確定待ち、音声装置の遅延は含まない。ビルド12実装の全文は89.28秒と93.68秒の音声となり、生成時間は21.01秒と22.00秒、上限による再生成は0回だった。設定の切り替えや初回準備には別に時間が必要。

登録音声との話者埋め込み類似度の中央値は、元の0.877からビルド12実装で0.833になった。この値は本人に聞こえる割合ではなく、声質の維持を保証するものでもない。強めのノイズ低減より穏やかな設定を採用し、画面からOFFにして比較できるようにした。

## 対策

- 参照音声をモデルのサンプルレートにそろえ、20msフレームの静かな15%から定常ノイズを推定する。発話と静かな部分の差が不足する場合や、ノイズが極めて小さい場合は処理しない。
- 既存のnoisereduceで穏やかに処理し、元録音の全文・長さ・順序を保つ。元ファイルに書き込まず、処理結果をメモリ上にキャッシュする。
- 参照録音の更新、サンプルレート、ノイズ軽減ON/OFFでキャッシュを更新する。返信待ちの準備で処理し、各行のたびに処理し直さない。
- 「読み上げ・返信」→Qwen→「参照音声の背景ノイズを軽減」を初期ONにする。声の響きが気になる場合は、既存の試聴欄でOFFと比較する。
- 復号方式や生成温度の変更には十分なノイズ低減効果が見られず、採用していない。読み上げの語句や固有名詞を自動で置き換える変更も行っていない。

## Sarashina2.2-TTSの検討

日本語に重点を置き、短い参照録音から声を再現する音声合成モデルとして候補になる。[公式モデルカード](https://huggingface.co/sbintuitions/sarashina2.2-tts)

ただし、現在のMac版にそのまま差し替える構成ではない。確認した公式実装の自動デバイス選択はCUDAまたはCPUで、高速化の案内もvLLM/CUDAが中心。MPSを明示指定できるコードはあるが、このMacで全工程が動くことや開始速度は未検証。今回調べたMLX Audioの公式TTSモデル一覧にもSarashinaの記載はなかった。[公式推論コード](https://github.com/sbintuitions/sarashina2.2-tts/blob/main/sarashina_tts/generate/generate.py)、[MLX Audioの対応モデル](https://github.com/Blaizzy/mlx-audio/blob/main/docs/models/tts/index.md)

公式の依存関係はTransformers 4.57.6、PyTorch 2.9以下、音声トークナイザー、Flow、透かし処理などを含み、現在の実行環境とは別環境で検証する必要がある。また、モデルは非商用ライセンスで、研究評価と業務利用を区別する必要がある。商用利用について公式は問い合わせを案内している。今回は重みのダウンロードやアプリへの組み込みを行っていない。[依存関係](https://github.com/sbintuitions/sarashina2.2-tts/blob/main/pyproject.toml)、[モデルの利用条件](https://github.com/sbintuitions/sarashina2.2-tts/blob/main/LICENSE)

## 再現手順

`scripts/diagnose-speech.py`にリポジトリ外の入力ファイルと出力先を指定し、ネットワーク禁止下で実行する。既存の設定からローカルのモデルと参照音声だけを読み、音声・本文・認識結果をリポジトリ外に保存する。原音条件は`--raw-reference`、比較条件は`--whole-decode`、`--temperature 0.6`、`--clean-reference --reference-reduction 0.65`などで指定できる。指定なしは現在のworker実装を使う。
