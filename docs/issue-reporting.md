# 不具合報告

アプリを使って困った場合は、[GitHubの報告フォーム](https://github.com/nyasukun/talk-to-webex-bot/issues/new?template=bug_report.yml)から報告できます。原因が分からなくても、再現しなくても構いません。期待した結果、実際の結果、操作の順番、発生頻度、試した対処を記入してください。

## アプリから下書きを作る

1. 待受や録音を停止し、サイドバー・ログ・ヘルプの「不具合を報告」を開きます。
2. 環境情報と直近30件の診断イベントを確認し、症状と再現手順を追記します。
3. 「下書きをコピー」を押し、GitHubの報告フォームを開きます。
4. 該当する欄へ貼り付け、公開してよい内容か確認して投稿します。

ログは本文を含まない既知のイベントと数値だけです。報告にはトークン・宛先・合言葉・会話・設定JSON・ローカルパス・画面画像・録音を自動添付しません。手で追記した内容にも個人名、内部URL、ユーザ名を含むパスなどがないか確認してください。認証情報の漏洩など機密性のある問題は、公開Issueへ詳細を載せないでください。

報告画面の編集はメモリ内だけで、閉じると破棄されます。残したい場合は先にコピーしてください。GitHubフォームを開くURLに本文やログは含めません。

## 起動できない場合

リポジトリのディレクトリで実行します。

```bash
mkdir -p .build
python3 scripts/collect-issue-report.py > .build/issue-report.md
```

Python標準ライブラリだけを使い、macOS・CPU・ソースのバージョン・コミット・ツールの有無を確認します。設定・キーチェーン・録音・診断ログは読みません。ソースの版は起動中アプリの版と異なる場合があるため、分かる場合は両方を記入してください。

Codexなどリポジトリ内スキルに対応する環境では `$talk-to-webex-bot-report-issue` を指定できます。下書き作成だけの依頼で自動投稿はしません。「GitHubに報告して」と依頼した場合は、利用可能な認証済みツールで投稿し、作成したIssueのURLを返します。

## 開発者向け

`IssueReport.swift` は共有可能な項目だけを明示的に組み立てます。新しい設定フィールドを追加しても自動的に報告へ入りません。自由文エラー・認識結果・送信本文を追加しないでください。CLIも情報を限定して取得します。回帰テストは `HardeningTests.swift` と `Tests/ScriptTests` にあります。
