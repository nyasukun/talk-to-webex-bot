# Talk to Webex botのサポート

このリポジトリのMac向けローカル音声アシスタントを支援する。まず作業ディレクトリ、Git状態、適用されるAGENTS.mdを確認する。Package.swift、worker/relay_worker.py、scripts/build.shがあるリポジトリ内で作業し、別プロジェクトや個人共通設定へ変更を広げない。

## 作業の選び方

- インストール・更新：[README](../../../README.md)の導入手順と[署名手順](../../../docs/signing.md)を読む。Macのチップ・メモリ・OS、既存のPython環境・モデル・署名を確認し、不足するものだけ準備する。取得はscripts/setup-runtime.shとscripts/download-models.sh、ビルドはscripts/build.shを使う。実行中のアプリを上書きしない。既存の署名証明書を再利用し、別署名やアドホック署名へ自動で切り替えない。
- 不具合：[トラブルシューティング](../../../docs/troubleshooting.md)を症状に合わせて読む。最初にログ画面の分類・エラー・診断数値を確認し、送信しないテストで原因を絞る。修正時は関係するテストとscripts/test.shを実行し、[検証記録](../../../docs/validation.md)で確認済みと未確認を区別する。
- 操作説明：[README](../../../README.md)と[E2E手順](../../../docs/e2e.md)の該当部分を読む。現行UIの項目名はSources/LocalVoiceRelay/Views/ の各ビューで確認する。操作を一度に大量に依頼せず、結果で次の一手を決める。
- モデル・声：[モデル資料](../../../docs/models.md)を読む。本人の声の優先・厳格な照合と、読み上げ用の参照音声は別機能。短い指示の利便性には優先モードを使う。参照録音を登録しただけで追加学習済みと呼ばない。

GitHubへの不具合報告は [Issue報告スキル](../talk-to-webex-bot-report-issue/SKILL.md)を使う。アプリの「不具合を報告」または `scripts/collect-issue-report.py` で下書きを作り、既存の投稿許可の範囲で進める。

## このアプリ固有の注意点

- 実際のAPI Key、DMの宛先、合言葉、会話、画像、OCR、録音、話者データはユーザのローカル設定として扱う。認証情報をチャットへ貼るよう求めず、キーチェーンをCLIで読み出さない。診断ログはアプリ用フォルダのdiagnostics/events.jsonにあり、既知のイベントと数値だけを記録する。ログやユーザ設定をリポジトリへコピーしない。
- 通常の音声・OCR処理はMac内で完結し、workerはネットワーク禁止で起動する。モデルの自動取得を通常実行へ追加しない。アプリのAPI通信はWebexだけ。トークン失効時には既定ブラウザで公式取得ページを開く経路がある。
- APIの401は認証更新、429はRetry-After、送信成否不明はWebex側の確認が必要。成否不明のPOSTを自動再送しない。サポートの相談だけを外部への送信許可とは扱わない。
- キーチェーンの許可とトークンの12時間の有効期限は別。保存日時を発行日時として扱わない。保存済みトークンの読み込みでACLを書き換えない。
- 画面権限は権限画面で先に確認する。再ビルド後も同じ証明書とBundle IDを維持する。権限をリセットする前に、署名・実行パス・再起動を確認し、必要なら今回の対象と操作についてユーザの許可を得る。
- 返信の最終判定は更新停止の待ち時間に基づく。100msの監視間隔と、初期値6秒の更新停止待ちは別。実機の途中表示・同一ID更新・重複読み上げを[E2E手順](../../../docs/e2e.md)で確かめる。
- 返信用の合言葉は直前にアプリで受け取った返信のスレッドを使う。初期値は新しい文字起こしと、会話を引き継ぐ指示・読み上げ表記の指示を送る。直前のボット回答の本文は引用せず、スクショも付けない。確認画面の引用は返信先確認用で送信されない。返信先を推測して別の会話へ送らない。
- 常時待受は25秒の音声区間超過や指示受付の期限で終了しない。該当区間を破棄して次の合言葉へ戻る。画面ロックとOSのログアウト・スリープを区別し、ロック中の実動作はE2Eで確認する。スクショを取得できない場合は画像とOCRを省いて音声の指示だけで続行する。
- 長い読み上げは句読点・記号・改行で事前分割する。生成上限では未再生の区間だけ再分割し、再生成する。再分割回数はログで確認し、参照音声での聴感を未検証のまま改善済みとしない。
- UIの変更は[UI/UXレビュー](../../../docs/ux-review.md)も読み、ホームの次の操作、保存・取り消し、診断ログへの分離を保つ。
- 公開するコード・コメント・文書・テストは一般的な例とWebexの情報だけを使う。社内固有情報や個人データを追加しない。公開前はscripts/audit-public.pyを実行し、ユーザ指定の除外語があれば保存せず引数で渡す。

変更とテストを完了してから必要な実機操作を依頼する。確認できたこと、次に必要な操作、残る制約を短く説明する。
