# Talk to Webex bot

macOSで合言葉を受け付け、日本語の発話をローカルで文字起こしして、選択したWebex DMへ送るアプリです。必要な場合だけ前面ウィンドウの画像とVision OCRを添付し、相手の返信をローカル音声で読み上げます。

**ビルド・自動テスト・オフライン推論に加え、ユーザ操作による音声入力・本人照合・画像/OCR付きWebex実送信・同一IDの返信更新・本人参照音声での返信読み上げ・再ビルド後の権限保持を確認しました。実環境の音楽・雑音・別話者への誤反応率と長時間常駐は継続検証が必要です。** 検証範囲は[検証記録](docs/validation.md)、実施方法は[E2E手順](docs/e2e.md)を参照してください。

## 必要な環境

- Apple Silicon Mac、macOS 14以降。16GB以上を推奨。標準の声の再現モデル（Qwen3-TTS 1.7B・8bit）とWhisperを併用する場合は24GBを目安にしてください。16GBのMacでは省メモリの `voice-small`（0.6B・4bit）を選べます。
- Swift 6対応のCommand Line ToolsまたはXcode。`xcode-select --install` で導入します。
- Python 3.12とuv。Homebrew利用時は `brew install uv python@3.12`。
- Webex個人アクセストークン、送信可能なDM。トークンはアプリ内のSecureFieldへ入力します。
- 初回取得用のインターネット接続と数GB以上の空き容量。

## セットアップと起動

このリポジトリを作業ディレクトリにして実行します。

```bash
# 初回のみ: 依存関係・Whisperモデルの取得と.app作成
scripts/setup.sh

# 本人の声を再現するQwen3-TTSも使う場合
scripts/setup.sh --voice

open "dist/Talk to Webex bot.app"
```

設定と参照音声、ランタイム、モデルは `~/Library/Application Support/LocalVoiceRelay/` に保存します。ソースやGitへ認証情報、宛先、実際の合言葉、本人の音声を追加しないでください。

処理を分けて実行することもできます。

```bash
scripts/setup-runtime.sh --voice  # 明示的なオンライン依存取得
scripts/download-models.sh asr    # 明示的なオンラインモデル取得
scripts/download-models.sh voice # 任意: 音声再現モデル取得（1.7B・8bit、約2.9GB）
scripts/download-models.sh voice-small # 任意: 省メモリの音声再現モデル（0.6B・4bit、約1.1GB）
python3 scripts/setup-signing.py # 初回のみ: ローカル署名証明書を作成
scripts/build.sh                 # ネットワーク不要のビルド
scripts/test.sh                  # ネットワーク不要のロジック検証
scripts/smoke-local.sh --voice    # 配置済みモデルの実推論。マイクは使わない
```

Python依存関係は `worker/uv.lock`、モデルのリビジョンは `scripts/models.lock.json` で固定しています。モデル取得時もTLS証明書を検証します。CAの問題がある環境ではPythonの信頼ストアを正しく設定し、証明書検証を無効化しないでください。

ビルド成果物は `dist/Talk to Webex bot.app` です。初回セットアップで、このMac専用の自己署名証明書をユーザのキーチェーンに作り、再ビルドでも同じ鍵を使います。秘密鍵はキーチェーン、署名の選択情報はアプリ用フォルダの `signing/profile.json` に保存します。システムの証明書信頼設定は変更しません。証明書の作り直し・削除は識別条件を変えるため、自動で行いません。

手動で署名する場合は[署名手順](docs/signing.md)を参照してください。旧表示名からの変更後も、Bundle ID `org.localvoicerelay.app`、設定保存先、キーチェーンのサービス名、既存の署名証明書は互換性のため維持しています。

再ビルド前にはアプリを終了してください。ビルドは署名検証済みの.appを同じパスへ入れ替え、実行中のアプリを上書きしません。配布用署名・公証は含みません。既存の開発用署名証明書を利用する場合は `SIGNING_IDENTITY` を設定できます。

以前のアドホック署名ビルドから切り替えるときは、画面収録の古い登録を一度削除して、今回の.appを許可し直してください。システム設定で許可済みに見えても旧署名に対する登録が残ることがあります。必要な場合はアプリを終了して `tccutil reset ScreenCapture org.localvoicerelay.app` を実行し、同じ場所の.appを再起動して「権限」画面から再登録します。この操作はこのアプリの画面収録許可だけをリセットし、マイクや他のアプリの許可を変更しません。通常のビルドでは実行しません。

アドホック署名は `SIGNING_IDENTITY=-` で明示的に選べますが、再ビルドで識別条件が変わり、許可の再登録が必要になります。仕組みは[Appleの署名要件資料](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)、ローカル証明書は[Appleのコード署名資料](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)を参照してください。

## アプリ設定

最初にサイドバーの「権限」でマイクと、スクショ有効時の画面収録を確認してください。起動時に不足をエラー表示し、必要な権限がない間は待受を開始できません。「許可を設定」はここで明示的に操作し、設定後に「再確認」、画面収録を変更した場合はアプリを再起動します。録音・画面取得の処理から権限要求は行いません。

1. **Webex**: トークンを「保存して接続確認」。DMを検索して選択します。未入力なら直近5件、部分一致フィルタを入力すると一致する宛先の直近5件を表示します。APIから新しい順に5件ずつ読み、5件そろったら取得を止めます。フィルタに一致する宛先が少ない場合は、5件そろうかページの末尾まで確認します。入力変更時は前の検索を中止し、約0.4秒後に再検索します。
2. **音声入力**: 合言葉を登録します。例は「オッケー、アシスタント」。複数の表記候補は改行で分け、各4文字以上にします。声の優先を使う場合は専用の参照音声を登録します。初期の判定方法は「登録した声を優先」です。
3. **送信内容**: 送信前確認を選びます。初期状態は確認あり・スクショなしです。スクショを有効にした場合だけ、画面収録の権限を確認してください。
4. **読み上げ・返信**: 必要な場合だけ返信監視を有効にします。まずMac標準音声で確認し、声の再現を使う場合はQwen3-TTSと参照録音を設定します。
5. **詳細設定**: 診断で依存関係・モデル配置・VADの実行を確認し、「変更を保存」→「待受を開始」。必要な権限がすべて許可済みになってから開始します。

マイク入力バーが動かない場合は停止し、「ログ」→「診断テスト」の「マイクを5秒テスト」で確認してください。これは録音をローカルで認識して表示するだけで、Webexへ送信しません。システム設定のサウンド → 入力で使用するマイクが選ばれていることも確認します。Macの追加音声処理は相性があるため初期OFFです。有効にすると他アプリの再生音量も下がることを実機で確認したため、会議の音量を維持したい場合はOFFで使ってください。

「オッケー、アシスタント。今日の予定を教えて」と続けて話すか、合言葉の後に一呼吸置いて指示を話せます。合言葉は本文から除きます。既定は1.2秒の無音で区切り、合言葉の後12秒間指示を受け付けます。録音1区間は25秒が上限です。長い背景音や会話が続いた場合はその区間と古い認識結果を破棄し、マイクを止めずに次の合言葉を待ちます。指示受付の時間切れや認識待ちの混雑でも待受を続けます。一呼吸置いて合言葉から話し直してください。

待受・録音・認識中・送信準備・確認・送信・返信待ち・読み上げ・エラーを画面に表示します。停止またはCommand + .で処理を止めます。読み上げ中はマイクを停止し、完了後にバッファを破棄して1秒待ってから待受に戻ります。読み上げへの割り込み発話には対応しません。

## 常時待受と画面ロック

待受時間自体に上限はありません。「音声入力」の「待受中の自動スリープを防ぐ」は初期ONです。待受を開始した間だけMacのアイドルによるシステムスリープを抑え、停止すると解除します。画面の消灯・ロックは妨げません。Macの蓋を閉じる、手動でスリープする、OSからログアウトする状態での実行は対象外です。

Macへログインし、認証・マイク権限を確認して待受を開始した後、画面をロックして使う構成です。ロック中はスクショとOCRを省きます。送信前確認がONなら確認画面で待つため、ロック解除後に送信してください。OFFの場合は設定どおり確認なしで送信します。ロック中のマイク継続・本人の声での読み上げは実機確認項目です。トークン失効、権限不足、復旧できない録音エラーは解決が必要です。

## 通信・保存・権限

アプリがAPIとしてHTTP通信するのは `https://webexapis.com/v1/` のみです。URLのホスト・スキーム・ポート・認証部分を検査し、リダイレクトは同一ホストでも追いません。認証更新の案内では、別途ユーザの既定ブラウザでWebexの公式取得ページを開きます。不具合報告では、ユーザの操作でGitHubの報告フォームを開きます。URLには本文やログを含めません。Python workerは必要な環境変数だけを引き継ぎ、認証情報やPythonの読込先を上書きする環境変数を渡しません。オフライン環境変数に加え、`sandbox-exec` のネットワーク禁止下で動かします。モデルの不足を検出しても取得スクリプトを自動実行しません。Mac標準読み上げもネットワーク禁止の子プロセスで実行し、未取得の日本語音声はシステム設定で事前に取得します。

- トークン: このMacのキーチェーンに保存し、同じ署名のアプリにアクセスを許可します。読み出した値は起動中のメモリで保持します。チャット、ログ、設定JSONに出力しません。
- 個人設定: アプリ用フォルダ内の `settings.json`、権限0600。フォルダは0700。
- 参照音声: ユーザが録音・選択したものだけアプリ用フォルダに保持。本人照合と声の再現は別ファイル・別設定。
- 一時録音・読み上げ: アプリ用フォルダ内で処理後に削除。画像とOCRはメモリ上に保持します。
- 標準ログ: 会話本文、OCR、画像、トークン、参照音声を記録しません。UIの直近の発話と返信はプロセス内だけに保持します。

スクショ/OCR無効時は画面取得もOCRも行いません。有効時は**合言葉と指示の認識後、確認画面を表示する前**に前面ウィンドウを取得します。アプリ自身が前面の場合、対象ウィンドウがない場合、途中で前面が変わった場合、ロック中、画像・OCRを取得できない場合は、画像とOCR説明ブロックを両方省いて音声の指示だけで続行します。画面全体へ自動で切り替えません。省略は確認画面とログに表示します。画面収録の権限不足は先に権限画面で解決してください。確認画面に表示した本文とPNGそのものを送信します。OCRが長くメッセージ上限を超えた場合も黙って切り捨てず停止します。

## 画面の使い方

Macの設定のように、サイドバーから項目を選びます。ホームは待受操作と会話、「Webex」は認証と直近5件のDM、「音声入力」は2種類の合言葉と声の優先、「読み上げ・返信」は声・試聴・待ち時間、「送信内容」は通常とスレッド返信のテンプレート、「権限」はマイクと画面収録、「詳細設定」はモデルのパスです。変更は画面下の「変更を保存」で適用し、「変更を取り消す」で保存済みの状態へ戻せます。未保存の変更がある状態の開始ボタンは「保存して待受を開始」と表示します。DM選択も同じ保存操作に従います。API Keyと参照音声は、それぞれの保存操作で該当項目だけを保存します。⌘,で設定を開けます。サイドバーの項目検索は「キーチェーン」「ポーリング」「ロック」などでも探せます。ホームには不足している準備と次の操作を表示します。

診断情報は「ログ」にまとめています。分類・検索・注意/エラーの絞り込み、表示中のログのコピー、消去ができます。最新500件をアプリ用フォルダ `diagnostics/events.json`（0600）に保存し、本文・宛先・認証情報は記録しません。[トラブルシューティング](docs/troubleshooting.md)を参照してください。UIの評価基準・変更理由・検証範囲は[UI/UXレビュー](docs/ux-review.md)に記録しています。

## スレッドへの追加返信

「音声入力」で返信用の合言葉を登録します。例は「オッケー、返信して」です。通常の合言葉とは別の言葉にし、空欄にすると無効になります。合言葉と指示を続けて話しても、一呼吸置いても使えます。

このアプリが直前に受け取った最終返信のスレッドへ返します。既にスレッド内にある返信では同じルートを使用します。初期値は、新しい文字起こしと「以上の会話のコンテキストとユーザ返信を踏まえ、直前の話題を引き継ぐ」という指示、読み上げ向けの表記指示です。直前のボット回答の本文は送信文に引用せず、スクショ・OCRも付けません。「送信内容」で自由に編集でき、文字起こしだけにしたい場合は `{{transcript}}` にできます。旧初期値だけを一度移行し、独自の編集は保持します。送信前確認の上部にある返信先の引用は確認用で、送信本文には含みません。

返信先は起動中のメモリだけに保持します。再起動・DM変更・次の通常送信で破棄し、不明な場合は送信しません。最終返信を受け取るには「レスポンスを読み上げる」をオンにしてください。Webexの[メッセージAPI](https://developer.webex.com/messaging/docs/messaging-mcp-server)にあるparentIdによるスレッド送信を使います。

メニューバーは、合言葉の受領後から指示受付・確認・送信中まで赤、Webex送信成功後から返信待ち・読み上げ中まで緑、次の合言葉を待つ状態に戻ると通常色になります。送信失敗・取り消し・停止は通常色に戻ります。

## リポジトリ専用のサポートスキル

[専用スキル](.agents/skills/talk-to-webex-bot-support/SKILL.md)で、導入・更新・不具合の切り分け・使い方を支援できます。このリポジトリを開いたタスクで `$talk-to-webex-bot-support` を指定してください。`.agents/skills` は[リポジトリ内のスキルの配置先](https://learn.chatgpt.com/docs/build-skills)です。共有の個人スキルフォルダにはインストールしません。

他の利用者が困ったときは、[Issue報告スキル](.agents/skills/talk-to-webex-bot-report-issue/SKILL.md)を `$talk-to-webex-bot-report-issue` で呼び出せます。症状・再現手順・環境情報を整理し、投稿依頼がある場合はGitHub Issueの作成まで支援します。GitHubの認証済みツールがない場合も、下書きと[報告フォーム](https://github.com/nyasukun/talk-to-webex-bot/issues/new?template=bug_report.yml)を使えます。

アプリでは停止中にサイドバー、ログ画面、または「ヘルプ」から「不具合を報告」を開きます。アプリとmacOSの版、機能のオン／オフ、直近30件の診断イベントを下書きに入れ、内容を編集・コピーできます。トークン・宛先・合言葉・会話・パス・録音は自動添付しません。GitHubを開くだけでは投稿されません。起動できない場合は `python3 scripts/collect-issue-report.py` で環境情報付きの下書きを作れます。このスクリプトは設定・ログ・キーチェーンを読み取らず、通信もしません。詳しくは[不具合報告](docs/issue-reporting.md)を参照してください。

ホームの「表示を消去」は、このアプリ内の会話・直近の認識結果・スレッド返信先を消去します。Webex上のメッセージは残ります。ログの消去は、誤操作を避けるため確認後に実行します。

## アイコンと開発時の検証

imagegenで生成した[アイコン](Resources/AppIcon.png)をDock・Finder・サイドバーに使用します。生成プロンプトは[アイコンの記録](Resources/AppIcon.md)に残しています。変更時は `scripts/build-icon.sh` でICNSを再生成し、目視確認後に `scripts/audit-public.py` の承認済みハッシュを更新してください。通常のビルドでは同梱ICNSを使います。

`scripts/test.sh` でSwift・worker・報告スクリプトのテスト、`scripts/render-ui.sh` でサンプルデータによる画面描画、`python3 scripts/audit-public.py` で公開前監査を実行します。コミット直前には `python3 scripts/audit-public.py --staged` でGitのステージにある内容を検査できます。CIはmainへのpushとPull Requestで同じテスト・監査・未署名のパッケージ作成を実行します。モデルや認証情報はCIに渡しません。

## Webex認証と送信エラー

個人トークンはDeveloper Portalへのサインインから12時間で失効します。保存日時を発行日時と決めつけず、分かる場合だけ実際の発行日時を入力します。起動中は5分ごと、および送信直前に `/people/me` で確認します。個人トークンの自動更新は行いません。401では停止し、既定ブラウザで公式の取得ページを開き、API Keyの入力画面を表示します。同じ失効状態では自動でブラウザを開き直さず、有効なトークンの更新後に次の失効を案内します。継続的な本番運用にはOAuth integrationが公式の推奨経路です。このアプリは短命の個人トークンを手動更新するローカル構成です。[Webex認証資料](https://developer.webex.com/messaging/docs/getting-started)

429ではRetry-After（秒またはHTTP日時）まで通信を抑制します。返信取得は待って再開し、送信POSTは自動再送しません。タイムアウト、接続切断、5xx、送信後に解釈できない応答、送信中の停止では、すでに送れた可能性があるためDMを確認してください。安易に同じ指示を送らないでください。

## 起動時のキーチェーン確認

自動処理ではキーチェーンのパスワード画面を出しません。起動中は最初の読み出し結果を保持し、5分ごとのAPI確認や送信のたびに読み直しません。トークンの12時間という期限と、Macがアプリに保存済み項目へのアクセスを許す仕組みは別です。

アクセスが必要と表示された場合は、ホームまたは「Webex」設定に表示される「保存済みトークンを読み込む」を停止中に押します。「有効性を確認」はAPI確認用で、キーチェーンのパスワード画面は出しません。自動読み込みと手動操作後の失敗は別の案内にし、状態番号はログにも残します。このボタンは1回の読み出しだけを行い、許可設定の書き換えや自動再試行はしません。macOSの確認画面に「常に許可」があれば選ぶと、同じ署名のアプリによる次回の読み込みを許可できます。通常のトークン更新も値だけを変更します。新規項目は作成したアプリを信頼するmacOSの既定設定で保存します。キーチェーンのロック状態やOSの管理方針によって必要な確認は異なります。トークンが有効と表示されていれば、手動で読み直す必要はありません。

## 返信待ちの音と音声の準備

「読み上げ・返信」で、ソナー音と音量、ホットスタンバイを変更できます。どちらも初期ONです。返信監視中は約3秒間隔で小さな音を流し、最初の読み上げ音声が始まるまで続けます。停止・エラー・タイムアウトでも終了し、この間のマイクは停止します。

Qwenは返信待ちの間にモデルと参照音声を読み込み、無音の準備推論を行います。参照音声はメモリ上で整えてからモデルへ渡します。低域の雑音を除き、「参照音声の背景ノイズを軽減」（初期ON）で声と一緒に再現される背景音を抑え、音量を一定にそろえます。録音の長さと前後の無音はそのまま使い、元録音は変更しません。声の響きが気になる場合は試聴欄でノイズ軽減OFFと比べられます。生成した音声も区間ごとに音量をそろえ、行末の間を一定にしてから再生します。冒頭を短い文や自然な区切り（目安32文字以内）に分け、最初の音声ができた時点で再生します。続きは空行を除いた1行ごとに独立して生成します。Markdownに改行があり、通常本文と内容が同じ場合は改行を復元します。改行がない長文は文末で分割します。再生中はモデルが次の行を先行生成し、改行順に音声をつなぎます。モデルの推論は直列、音声再生は並行して進みます。待受に戻った後もモデルを保持し、「停止」で生成・先行音声を破棄して解放します。本文更新の停止を待つ時間は従来どおり確保します。ログ画面には準備状況と「返信確定から再生開始」に加え、行番号・生成秒数・音声秒数・再生残秒数を記録します。生成待ちで先行音声が尽きた場合もログに残ります。

## 読み上げに適した返信形式

送信テンプレートの初期値に、次の指示を含めています。以前の保存済みテンプレートには、編集内容を残して一度だけ追記します。その後は自由に変更・削除でき、削除しても再追記しません。

> あなたの返信は音声生成モデルで読み上げられます。日本語で返答を生成し、英語はその読みをカタカナで記載ください。また、短い一文として、改行して返信してください。
> 記号や装飾も、読み上げて意味が伝わる日本語に言い換えてください。
> 二桁以上の数字は、桁を一つずつ読ませず、意味に合った読みをひらがなで表現してください。全角数字も同様です。例：13時・１３時は「じゅうさんじ」、25分は「にじゅうごふん」、100は「ひゃく」と記載してください。

読み上げの本文は、Mac標準音声・Qwenの両方で読み上げ用に整えます。Markdownの見出し・箇条書き・太字・表・リンクは文字だけを残し、コードブロックは「コードは省略します。」に、URLは「リンク」に置き換え、絵文字を除き、「%」「℃」「→」などを読みに変えます。画面に表示する返信本文は変えません。

Qwenは1行の中の句読点を保ち、160文字以内の行はまとめて生成します。160文字を超える行だけ、句読点やmacOS内蔵の単語境界で事前分割します。生成が長さの上限に達した場合は、その未再生区間を破棄してさらに分割します。再生成した断片もそろえて1つの音声にしてから再生するため、行の途中に生成待ちを挟みません。再分割は最大3段階で、短い区間でも生成できない場合や不正な音声はエラーにし、全文をホームに残します。再生待ちが2区間以下かつ30秒以下になると次を生成するため、先行音声が無制限に増えることも防ぎます。長い生成や機器の負荷によって行間に待ちが出る可能性はあります。内容の反復や意味のない発声をすべて検出する仕組みではないため、実際の返答で確認してください。「読み上げ・返信」の試聴欄は編集でき、Webexへ送らずに長い文章を試せます。

## 返信判定

監視は「レスポンスを読み上げる」が有効な送信に限ります。新しいメッセージ一覧と候補IDの直接取得で、`Working...` から同じIDを編集する返信にも対応します。

自分自身、別DM、送信前のID・時刻、別のparentId、途中表示、同一内容の重複を除きます。別の自己送信が同じDMに入った場合は取り違えを避けるため監視を止めます。監視間隔の初期値は100msで、設定はms単位（100〜30,000）です。1回の取得処理が終わってから指定時間待つため、実際の取得間隔にはAPIの応答時間も加わります。429ではRetry-Afterを優先します。本文と更新時刻が6秒変わらなければ読み上げ、待ち時間の初期値は180秒です。期限後は返信監視とソナーを終了し、常時待受中なら次の合言葉の待受へ戻ります。送信は繰り返しません。以前の初期値2秒は初回読み込みで100msへ移行し、その他の既存の値は保持します。移行後に設定した2,000msも保持します。

**parentIdがないDM返信の関連付けと、更新停止による最終回答判定は推定です。** 以前の要求への遅延返信や6秒以上停止する途中回答を完全には区別できません。「スレッド返信だけ」を有効にすれば関連付けは厳しくなりますが、相手がスレッドを使わない場合は読み上げません。最初の安定した回答を読み終えたら監視を終了するため、その後の訂正は自動で読みません。実際の相手で[E2E手順](docs/e2e.md)に沿って待ち時間を調整してください。

## 自分の声

本人照合はResemblyzerの話者埋め込み比較、本人の声での読み上げはQwen3-TTSの参照音声による再現です。別機能であり、照合を有効にするだけでは読み上げの声は変わりません。

静かな部屋でマイクから15〜25cm程度離れ、普段の声・一定の音量で10〜20秒録音してください。全体の音量はアプリ側でそろえます。前後に1秒程度の無音があっても構いません。アプリの「参照音声を録音」はWAV・モノラル・24kHz・16bit、最大30秒です。別ファイルを用意する場合もWAVを推奨します。本人照合には少なくとも3秒の音声区間が必要です。

読み上げ例:

> 今日は予定を確認します。必要な情報を整理して、順番に作業を進めます。画面に表示された内容を読み取り、分かりやすく説明してください。

声の再現用には実際に読んだ文章を参照本文欄に正確に入力してください。言い間違いがあれば録り直すか、実際の発話に合わせます。録音後「この設定で読み上げを試す」で音量・発音・声の似方を確認してください。

参照方式は音声を推論時の手掛かりに使います。追加学習は大量の音声と書き起こしでモデルの重みを更新する別工程です。この用途では短い参照方式を採用し、追加学習は実装していません。録音や試聴なしに「本人の声を学習済み」と扱いません。

音楽や他人の声への誤反応は、任意のMac追加音声処理、フィルタ、ノイズ抑制、VAD、Whisperの信頼度、登録した声の判定で減らします。判定方法は次の2つです。

- **登録した声を優先（初期値）**: 利便性のための機能です。短い指示や低い類似度だけでは拒否しません。1回の録音内に、間を置いた複数の声を十分な確度で区別できる場合、登録した声に近い発話を優先して文字起こしします。不確かな区間や短い区間は残します。単独の他人の発話も合言葉が一致すれば受け付けます。同時に重なる声の分離や、別々の録音をまたいだ話者選択は行いません。
- **厳格に本人照合**: 指示に1.6秒以上の音声区間が必要です。全体と1.6〜3秒の窓を照合し、しきい値に届かない場合は止めます。短い発話を受け付けたい場合は優先モードを使ってください。

「マイクを5秒テスト」は待受と同じ録音経路・設定を使います。優先モードの類似度は参考値で、単独発話を拒否するしきい値ではありません。どちらも録音再生を防ぐ認証機能ではありません。誤送信を減らしたい場合は送信前確認を使ってください。

## モデル選定と構成

責務の分担と変更時の検証は[構成と変更の境界](docs/architecture.md)を参照してください。

Whisper turbo（MLX）を既定とし、large-v3を比較用に選択できます。Sarashinaの配布条件、Mac対応状況、Qwenの選定理由、測定条件は[モデル比較](docs/models.md)を参照してください。

- `Sources/RelayCore`: テンプレート、合言葉、設定、Webex通信、返信判定
- `Sources/LocalVoiceRelay`: SwiftUI、状態管理、録音、Vision OCR、キーチェーン、worker連携
- `worker`: JSON Linesで動くローカル推論と固定依存関係
- `scripts`: セットアップ、取得、ビルド、オフライン検証、公開前監査

公開前は `python3 scripts/audit-public.py` を実行し、非公開語句はローカルから `--forbid` で追加検査できます。設定、実録音、モデル、ビルド成果物をコミットしないでください。外部モデルとライブラリのライセンスは各配布元の条件に従います。
