# 実機E2Eの確認手順

実送信はテストしてよいDMをアプリで選んでから行います。宛先・トークン・実際の合言葉・録音・本文・画像を公開のissueやログに貼らないでください。結果を記録するときは成功/失敗、時間、状態遷移だけを残します。

## 1. 起動と認証

- `scripts/build.sh` で作った.appを同じ場所から起動できる。
- 起動時に「最初に権限を確認」でマイクと、スクショ有効時の画面収録状態が出る。未許可ならエラーを表示し、待受を開始できない。ここで明示的に許可を設定し、再確認する。画面収録の変更後はアプリを再起動する。
- 「Webex」設定でトークンを保存し、有効表示が出る。保存時刻を期限と誤表示しない。
- DMが直近5件だけ表示される。部分一致のフィルタを入力すると、一致した宛先の直近5件に切り替わる。5件未満なら存在する候補だけ表示する。素早く入力を変えても古い検索結果が戻らず、選択済み宛先が自動で変わらない。
- 宛先を選んだ後、上部に選択したDMが出る。

## 2. 送信と返信更新

1. スクショOFF、送信前確認ON、返信読み上げON、Mac標準音声にして設定を保存。
2. 「ログ」→「診断テスト」から手動テストの確認画面を開く。本文にスクショ・OCR説明がないことを確認。
3. 確認画面の宛先と本文を見て送信する。
4. Webexで同じ本文が1件だけ送信されたことを確認する。
5. 相手が途中表示を出す場合、その状態では読まれないことを確認する。
6. 同一メッセージIDの本文が最終回答に変わった後、設定した安定時間を経て1回だけ読み上げることを確認する。
7. 古い返信・自分の送信・別スレッドを読まないことを確認する。

ログ画面の「返信の新着と同一IDの更新」には、今回の取得回数・返信候補件数・途中表示件数・同一IDの本文更新回数が残ります。同一IDの本文更新が1回以上なら、監視中の本文変更をアプリが観測しています。0回の場合、更新がなかったのか、取得の合間に完了したのかは区別できません。本文・IDをログへ保存する機能ではありません。

相手が独自の途中表示を使う場合は先頭フレーズを設定に追加します。途中回答が長く止まる相手なら安定待ち時間を延ばします。通常のDM本文には要求IDがないため、別要求への遅延回答との厳密な区別はできません。相手が対応していれば「スレッド返信だけ」を使います。

## 3. マイクと合言葉

- 操作前にマイクを許可し、待受を開始する。録音開始時に権限ダイアログが出ない。拒否・未許可なら操作前のエラーになり、許可と再確認後に開始できる。
- 「オッケー、アシスタント。接続を確認してください」のように続けて話す。合言葉を含まない指示が確認画面に出る。
- 合言葉だけ話し、一呼吸置いてから同じ指示を話す。受付時間内なら同じ結果になる。
- 合言葉だけで送信されない。受付時間を過ぎた発話が勝手に送信されない。
- 合言葉以外、無音、生活音、音楽、別話者で少なくとも数分確認する。誤作動を絶対に防ぐ保証はないため、必要に応じて本人照合と確認画面を有効にする。
- 25秒を超えた発話や処理待ちがあふれた場合は、途中の指示を送らず破棄し、待受を継続する。
- 読み上げ中に自分の声で再起動しない。読み終えた後、待受に戻る。
- マイク切替・抜き差し・スリープ復帰時に、停止と再開で回復できる。

## 4. 画面とOCR

- 初期状態では画面収録の要求がなく、スクショ無効時の送信に画像・OCRがない。
- スクショ有効時は、操作前に「権限」画面で許可する。拒否・未許可なら起動時・待受前にエラーになり、画面取得の最中に許可を求めない。
- 共有してよい一般的な文章のウィンドウを前面にする。
- テスト文には [screen-context-sample.txt](screen-context-sample.txt) を使える。テキストエディットで開き、待受を開始してからこの文のウィンドウを前面に戻す。
- 音声指示の後、確認画面でそのウィンドウだけのPNGとOCRを確認する。
- 確認画面を出した後に前面の内容を変更しても、送信されるのは確認済みの画像・本文のまま。
- 取得途中の前面アプリ切替、アプリ自身が前面、取得不可能なウィンドウでは、画面全体への自動切替や黙った画像省略がない。
- 取り消した場合は何も送られず、待受が停止する。

## 5. 本人照合と声の再現

別々に参照録音を作り、まず本人照合を試します。本人と別話者の類似度をアプリの診断表示で確認して、しきい値を調整します。録音再生によるなりすましを防ぐ認証機能としては扱いません。

声の再現はQwenを選び、本人の10〜20秒の参照録音と正確な本文を登録します。試聴で発音、間、音量、声の似方を確認します。「録音保存」「音声生成成功」「声質を本人が確認」を別の完了条件にしてください。追加学習を行ったと記載しないでください。

## 6. 障害ケース

- 無効トークンの401: 更新案内が出て停止する。
- 429: Retry-Afterまで抑制し、送信は再送しない。返信のGETだけ再開する。
- 通信切断・送信中停止: 成否不明を表示し、DM確認を促す。
- 返信タイムアウト: 送信済みであることが分かるエラーを表示する。
- モデルを未配置のパスに変更: 自動取得せず案内する。
- 読み上げ失敗: 未検証の音声へ黙ってフォールバックせず、停止して案内する。

401・429・通信切断は自動テストでも検証します。実サービスへの大量リクエストで429を意図的に発生させないでください。

## 7. 操作感と声の優先

1. 起動だけでキーチェーンのパスワード画面が出ないことを確認する。アクセス案内がある場合、「Webex」設定の「保存済みトークンを読み込む」を1回押す。macOSの確認に「常に許可」があればそれを選ぶ。再起動後も自動で有効性が確認されることを確認する。トークン期限切れの案内は別に扱う。
2. 声の判定を「登録した声を優先」、送信前確認ONにする。合言葉、一呼吸、短い指示で確認画面まで進むことを確認する。単独の他人の声を拒否するためのモードではない。
3. 実送信後、ソナー音が約3秒ごとに鳴り、音声待機が準備完了になることを確認する。返信確定後、本人の声で途中の不自然な切れ目なく再生され、ソナーが止まることを確認する。「返信確定から再生開始」の秒数を記録する。
4. 返信待ちと読み上げ途中のそれぞれで停止し、ソナー・音声が残らないことを確認する。待受を再開し、以前の音声が混ざらないことを確認する。
5. 許可を得た協力者と、同じ録音内に0.5〜1秒の間を置いて話す。登録した声に近い発話が優先されるか、送信せずプレビューで確認する。声が重なる場合や区別できない場合は発話を残すため、本文も確認する。実録音・参照データを公開記録に保存しない。


## 8. 改行ごとの読み上げと100ms設定

1. 「読み上げ・返信」の監視間隔が100msであることを確認する。変更して保存・再起動してもms単位の値が保持されることを確認する。本文更新停止の6秒と混同しない。
2. 「送信テンプレート」に、日本語・英語のカタカナ表記・短文改行・記号の言い換え指示が追記され、以前の編集内容が残っていることを確認する。
3. Qwenと保存済みの本人参照音声で、試聴欄の9文を再生する。英語・記号の読み、後半の反復や意味のない声の有無、文間の途切れ、最後の文まで読めることを確認する。試聴はWebexへ送らない。
4. 送信前確認を有効にし、宛先・本文を確認して、説明を求める一般的な指示を送る。実際の返信が日本語・カタカナ・1文1行になり、読み上げも最後まで正常であることを確認する。監視回数・更新回数・再生開始までの時間も確認する。
5. 相手が指示に沿わない場合はテンプレートを調整する。空行を挟んだ複数行を試聴し、行内の句読点を保ち、改行順に読まれることを確認する。最初の短い音声ができた時点で再生を開始し、再生中も次の行を生成する。改行が消えた長文でも冒頭から始まり、途中や末尾を飛ばさないことを確認する。Markdownの改行は通常本文と内容が同じ場合だけ復元する。行間の待ちが出たらログの行番号・生成秒・再生残秒・「先行音声が尽きた」を確認する。1行だけの返信と途中停止も試す。上限に達した場合は再分割の件数が残り、成功した断片を結合してから再生される。短い区間でも生成できないエラーでは全文をホームで確認する。

## 9. 設定画面・ログ・数字の読み

1. 左側にホーム、設定の各項目、ログが表示され、クリックとキーボードで移動できることを確認する。明暗の外観、ウィンドウを小さくした場合のスクロール、保存前の変更表示を確認する。
2. 「送信内容」で、二桁以上・全角の数字を意味に合ったひらがなへ変換する指示が追加され、以前の編集が残っていることを確認する。一度追加された指示は編集・削除できる。
3. 送信前確認をオンにし、一般的な予定を「１３時からの予定を一文で返してください」と依頼する。プレビューの宛先と本文を確認して送信し、返信が「じゅうさんじ」と表記され、正しく読まれるか確認する。ボットが指示に従うことと、音声モデルの発音は分けて評価する。
4. 「ログ」で送信・返信更新・読み上げの時刻と数値を確認し、分類、検索、注意・エラーの絞り込みを試す。会話本文・宛先・認証情報がイベントに含まれていないことを確認する。

## 10. スレッドへの追加返信・メニューバー

1. 「音声入力」で返信用の合言葉を確認し、「送信内容」のスレッド返信テンプレートを「初期の返信テンプレートに戻す」で初期値にする。送信前確認と返信読み上げをオンにする。
2. 通常の送信で相手の最終返信を受け取る。合言葉の検出後にメニューバーが赤、Webexへの送信成功後に緑、次の待受で通常色へ戻ることも確認する。
3. 返信用の合言葉（例：オッケー、返信して）の後に「もう少し短く説明してください」と話す。確認画面で、新しい文字起こしと会話を引き継ぐ指示・読み上げ表記の指示が送信本文にあることを確認する。上部の引用は返信先の確認用で、送信本文にボットの前の回答・合言葉・スクショが含まれないことを確認する。
4. 確認して送信し、Webexで同じスレッド内に追加され、相手の返信更新と読み上げが一度だけ行われることを確認する。連続発話と一呼吸置く発話の両方を試す。
5. DMを切り替えた場合と再起動後には、通常の返信を受け取るまでスレッド返信が送られず案内が出ることを、送信せず確認する。返信監視オフの場合も新しい返信先は取得しない。

## 11. 認証の更新案内

1. 通常使用で401が発生したとき、既定ブラウザに公式取得ページが開き、アプリにAPI Keyの入力画面が表示されることを確認する。期限切れを再現するために有効な保存済みトークンを壊す必要はない。
2. 更新を後回しにしても定期確認のたびにブラウザが増えないこと、Webex設定から入力画面を再表示できることを確認する。
3. 新しいPersonal Access Tokenをアプリ内だけに入力して保存し、有効状態へ戻ることを確認する。入力途中にバックグラウンドの有効性確認で画面が閉じないことも確認する。
4. ブラウザ起動は差し替えた処理で自動テストする。実トークンやブラウザの認証済み画面を検証資料へ保存しない。

## 12. 会議中の内蔵マイク

1. 会議を開始し、macOSのサウンド設定と会議アプリで内蔵マイクを選ぶ。アプリは停止状態から「ログ」→「診断テスト」→「マイクを5秒テスト（送信なし）」を実行する。
2. 合言葉と短い指示を話し、入力バー、録音の秒数・入力最大値・入力Hz・認識結果を確認する。録音は一時保存後に削除され、Webexへ送られない。
3. 音声フレームが届かない場合と、入力音量がゼロの場合は別の案内になる。ログの入力途絶・再接続も確認する。入力音量がゼロのままなら、macOSの入力音量・マイクモードを確認する。
4. 待受中に会議を開始・終了し、バーが継続して動くか、再接続の案内後に復帰するか確認する。再接続時の途中発話は破棄するため、合言葉から話し直す。確認画面が出たら取り消しでよい。
5. 音声形式変更や4秒のフレーム途絶に対する再接続は30秒に2回まで。制限後は停止して案内し、無制限の再起動や指示の再送をしない。単なる無音とフレーム途絶は区別する。

## 13. 常時待受・画面省略・ロック

1. 送信前確認をONにし、待受を開始して2分以上待つ。合言葉を含まない一般的な会話を25秒以上続けても停止しないことを確認する。一呼吸後の合言葉と短い指示で確認画面を開けることを確認し、取り消す。
2. 画面収録の権限を先に許可し、スクショ/OCRをONにする。このアプリ自身を前面にして合言葉と指示を話す。画面を前面にするよう求めるエラーではなく、画像・OCRが省かれた確認画面が出る。内容と宛先を確認して送信する。
3. 「待受中の自動スリープを防ぐ」をONにし、待受を開始してMacをロックする。1分後に合言葉と短い指示を話す。ロックを解除し、画像・OCRを含まない確認画面で待っていることを確認する。ロック前に確認画面が開いていたケースとは分けて試す。
4. 確認なし送信も使う場合は、テスト用DMを選び送信前確認をOFFにしたことを自分で確認してから、ロック中の実送信と読み上げを試す。テスト後は普段の設定へ戻す。ロック解除パスワードやトークンをアプリ以外へ渡さない。
5. 返信がないケースでは、設定した期限後にソナーが止まり次の合言葉を受け付ける。元の指示が再送されていないことをWebexで確認する。

## 14. 設定とログの操作

1. DMと数値を変更すると未保存表示になり、「変更を取り消す」で両方が戻る。API Keyの保存や参照音声の登録によって、別の未保存設定まで保存されない。
2. ホームに準備不足の理由と解決するボタンがある。検索で「キーチェーン」「ポーリング」「ロック」を探せる。待受中は設定の編集が無効になり、停止操作が表示される。
3. キーチェーンアクセスが必要なとき、読み込みボタンが折り畳みの外にある。手動でも拒否された場合の案内とログの番号を確認する。自動API確認だけでパスワード画面を期待しない。
4. 最小ウィンドウ・暗い外観でも項目、保存/取り消し、ログ検索にアクセスできる。ログの診断テストを開いても履歴が残り、5秒テストでは録音の進捗が表示される。VoiceOverとキーボードだけの操作は別途実施して記録する。

## 追加発話の連結と最後の送信への返信

- 音声入力で区切る無音1.2秒、追加発話をつなぐ無音3.6秒、送信前確認OFFにする。合言葉と一般的な指示を話し、1.2秒の無音で最初の送信が始まることを確認する。実際の投稿までには文字起こし・画面取得・API通信の時間が加わる。
- 最後の声から2秒程度で追加の条件を話す。続きが3.6秒を越えても最後まで録音され、1.2秒の無音後に「最初の指示＋追加条件」が新規メッセージとして送られることを確認する。3回目も累積した全文になることを確かめる。
- 最後の声から3.6秒を過ぎて話した内容は連結されないことを確認する。認識中・送信中に話した続きも、実際の音声時刻で判定されることを確認する。
- 最後の送信より後に、最初の送信へ返信する。その回答は読み上げず、最後の送信を返信先にした回答だけを、本文更新の停止待ち後に一度読み上げることを確認する。返信先情報のない回答は再送後には読まない。同じスレッド内で複数送信した場合は、返信の特定不可の案内がログに出ることを確認する。
- 送信前確認ONでは、発話をつなげた全文だけが確認画面に出て、確認前の投稿がないことを確認する。読み上げOFFでも追加発話の再送は行われ、終了後は待受に戻ることを確認する。
- 追加発話の録音中・送信中・返信監視中に停止し、停止後に送信・読み上げが再開しないことを確認する。送信成否不明では自動再送しない。
